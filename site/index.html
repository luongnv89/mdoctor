Problem

Disks fill up at the worst moment

mdoctor is for developers and power users on macOS or Debian Linux whose machine slows down and who do not trust opaque cleaner apps with delete access.

Scenario 1

Deploy blocked by 800 MB free

Xcode DerivedData, node_modules, and old logs eat the disk. You hunt folders by hand before a release.

Scenario 2

Boot takes minutes, fan never stops

Login items pile up, a runaway process pins CPU, swap grows. Activity Monitor shows symptoms, not causes.

Scenario 3

Updates and dotfiles drift

Homebrew or APT lags behind, Git and SSH config silently break, Docker leaves gigabytes of stopped containers.

Cost of inaction

Guessing costs more than checking

Manual cleanup is slow and risky. Each month without a repeatable audit adds failure modes.

Consequence 1

Hours lost to manual triage

du, log hunts, and forum threads replace one scored audit with history trends and next steps.

Consequence 2

Wrong file deleted under pressure

A rushed rm -rf in ~/Library or ~/.cache removes the wrong cache. mdoctor gates every deletion behind validators and an explicit confirm.

Consequence 3

Small warnings become outages

A full disk corrupts a build, an expired backup goes unnoticed, a weak firewall setting ships to a café network.

Solution

One CLI: check, clean, fix, benchmark

mdoctor runs read-only health checks, previews cleanup in dry-run, prints fixes with a [DRY RUN] prefix, and measures disk, network, and CPU. Pure Bash, so you can read every line it will run.

Outcome

See system health as a score

0–100 with warnings, a markdown report in /tmp, and history that flags drops such as 92 → 64 since the last run.

Outcome

Preview before anything is removed

mdoctor clean lists bytes per target first. Force mode prints a pre-flight summary and asks Proceed with deletion? [y/N].

Outcome

Fix with copy-paste confidence

mdoctor fix dns, fix apt, fix wifi, and 7 more print exact commands first. Diagnose correlates CPU, memory, disk I/O, swap, and zombies into a prioritized remedy list.

Outcome

Automate without a daemon

mdoctor check --json pipes into your scripts. Benchmarks pin network to one HTTPS host you can override with MDOCTOR_BENCH_HOST.

FAQ

Answers before you install

Does mdoctor change anything when I run check?

No. All check modules are [SAFE] and read-only. Reports go to /tmp and score history stays in your home directory.

How do I avoid accidental deletion?

Stay on the default: mdoctor clean runs in dry-run and lists what would go. Deletion needs --force plus an explicit y, or MDOCTOR_ASSUME_YES=true for scripts. Piping from a non-tty without that variable refuses outright.

Which systems are supported?

macOS and Debian-family Linux (Ubuntu, Pop!_OS, Mint, Raspbian). Modules gate on lib/platform.sh predicates, never on raw uname checks.

What does it need installed?

Bash 3.2 or newer, git on Linux for install, and standard system tools. No vendored dependencies and no build step.

Can I target one thing instead of everything?

Yes. mdoctor check -m battery, mdoctor clean -m trash, mdoctor fix dns, and mdoctor list for the live module set on your OS.

How do I remove it?

Run the uninstaller or delete two paths: the install dir (~/.mdoctor by default) and the binary link (/usr/local/bin/mdoctor). Custom prefixes use MDOCTOR_INSTALL_DIR and MDOCTOR_BIN_LINK.
